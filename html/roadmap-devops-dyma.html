PHASE
01

Fondations Système & Linux

⏱ 4 à 6 semaines Débutant
Compétences clés
  • Navigation et gestion du système de fichiers Linux
  • Permissions, utilisateurs, groupes
  • Gestion des processus, services (systemd)
  • Protocoles SSH, SCP, FTP
  • Scripting Bash avancé et automatisation
  • Gestion des paquets via APT et Snap
  • Planification de tâches (cron, anacron)
Pourquoi c'est essentiel
  • Linux est le système d'exploitation de 90 % des serveurs de production
  • Tous les outils DevOps (Docker, K8s, Ansible…) tournent sur Linux
  • Le shell Bash est le premier outil d'automatisation d'un DevOps
  • SSH est la méthode d'accès principale aux serveurs distants
  • Sans cette base, aucune autre phase n'est accessible
📚 Formation Dyma recommandée
Formation Linux & Bash — Terminal, scripts shell, SSH, permissions, cron, APT dyma.fr/formations/linux-bash ↗
Ubuntu / Debian Bash SSH cron systemd vim / nano
🏁 Jalon — Passer à la Phase 2 quand vous pouvez :
  • Naviguer et manipuler le système de fichiers Linux sans documentation
  • Écrire un script Bash complet avec boucles, conditions et gestion d'erreurs
  • Se connecter en SSH à un serveur distant et configurer les clés publiques
  • Gérer des services systemd et planifier des tâches cron
  • Administrer les permissions utilisateurs et groupes sur plusieurs fichiers
PHASE
02

Versionning, Réseaux & Serveurs Web

⏱ 4 à 6 semaines Débutant → Intermédiaire
Compétences clés — Git
  • Commits, branches, merges, rebases
  • Travail collaboratif : pull requests, code review
  • Stratégies de branching (Git Flow, trunk-based)
  • Gestion des conflits et tags de version
Compétences clés — NGINX
  • Configuration d'un serveur HTTP/HTTPS
  • Virtual hosts, reverse proxy, load balancing
  • HTTPS avec Let's Encrypt / TLS 1.3
  • Gestion des performances et du cache
  • Monitoring basique avec NGINX Amplify
📚 Formations Dyma recommandées
Formation Git — Versionning, branches, collaboration, GitHub dyma.fr ↗
Formation NGINX — Serveur web, reverse proxy, TLS, load balancing, monitoring dyma.fr/nginx ↗
Git GitHub NGINX Let's Encrypt TLS / SSL TCP/IP DNS
🏁 Jalon — Passer à la Phase 3 quand vous pouvez :
  • Gérer un dépôt Git collaboratif avec branches et pull requests
  • Configurer un serveur NGINX avec HTTPS sur un VPS
  • Mettre en place un reverse proxy pointant vers une application
  • Configurer un load balancer simple avec NGINX
  • Expliquer les bases TCP/IP, DNS, HTTP/2, WebSocket
PHASE
03

Conteneurisation avec Docker

⏱ 4 à 6 semaines Intermédiaire
Compétences clés
  • Images Docker : écriture de Dockerfile optimisés
  • Gestion des conteneurs, volumes, réseaux
  • Docker Compose pour les architectures multi-services
  • Docker Hub & registres privés
  • Sécurité des images et bonnes pratiques de production
  • Débogage et inspection de conteneurs
Pourquoi c'est essentiel
  • Docker est le prérequis absolu à Kubernetes
  • La conteneurisation est le paradigme dominant du déploiement moderne
  • Tous les pipelines CI/CD utilisent des conteneurs
  • Permet la portabilité et la reproductibilité des environnements
  • Indispensable pour Ansible, GitLab CI, GitHub Actions
📚 Formation Dyma recommandée
Formation Docker — Images, conteneurs, réseaux, volumes, Compose, déploiement dyma.fr/formations/docker ↗
Docker Docker Compose Dockerfile Docker Hub Container Registry YAML
🏁 Jalon — Passer à la Phase 4 quand vous pouvez :
  • Écrire un Dockerfile multi-stage optimisé pour la production
  • Déployer une stack complète (app + base de données + reverse proxy) via Docker Compose
  • Gérer les volumes persistants et les réseaux Docker personnalisés
  • Publier et versionner des images sur un registre privé
  • Déboguer un conteneur défaillant via les logs et exec
PHASE
04

CI/CD & Automatisation des Pipelines

⏱ 5 à 7 semaines Intermédiaire → Avancé
GitHub Actions
  • Workflows YAML et déclencheurs d'événements
  • Jobs, steps, runners (GitHub-hosted & self-hosted)
  • Gestion des secrets et des variables d'environnement
  • Déploiements multi-environnements (staging, prod)
  • Intégration Docker dans les workflows
GitLab CI/CD
  • Pipelines YAML : stages, jobs, scripts
  • Runners auto-gérés et optimisation
  • Artefacts, cache, gestion des dépendances
  • Intégration Docker et Container Registry
  • Déploiements automatiques sur environnements
Pourquoi maîtriser les deux
  • GitHub Actions est l'outil CI/CD le plus utilisé dans les startups et open source
  • GitLab CI/CD domine les environnements d'entreprise et on-premise
  • Les concepts sont transférables : maîtriser l'un accélère l'apprentissage de l'autre
  • Automatiser les tests, builds et déploiements est le cœur du métier DevOps
📚 Formations Dyma recommandées
Formation GitHub Actions — Workflows CI/CD, runners, Docker, déploiements automatisés dyma.fr/formations/github-actions ↗
Formation GitLab CI/CD — Pipelines, runners, Docker, artefacts, environnements dyma.fr/gitlabcicd ↗
GitHub Actions GitLab CI/CD YAML Docker in CI Secrets Management Runners
🏁 Jalon — Passer à la Phase 5 quand vous pouvez :
  • Créer un pipeline CI/CD complet (lint → tests → build → push image → déploiement)
  • Configurer des environnements de staging et production séparés
  • Gérer les secrets de manière sécurisée dans les deux plateformes
  • Mettre en place un runner self-hosted et l'optimiser
  • Déclencher des déploiements conditionnels selon la branche ou le tag
PHASE
05

Cloud, IaC & Orchestration Kubernetes

⏱ 8 à 12 semaines Avancé
AWS (Cloud)
  • EC2, VPC, IAM, S3, RDS, Lambda
  • CloudFront, Route 53, Load Balancers
  • Sécurité : rôles IAM, groupes de sécurité
  • Architecture serverless et haute disponibilité
  • CloudWatch pour le monitoring basique
Terraform / OpenTofu (IaC)
  • Langage HCL : ressources, variables, outputs, modules
  • Gestion du state (remote state sur S3, locking)
  • Multi-environnements (dev/staging/prod) avec workspaces
  • Pipeline CI/CD Terraform avec GitHub Actions
  • Sécurité : Checkov, HashiCorp Vault
  • Préparation certification Terraform Associate
Ansible (Gestion de config)
  • Inventaires statiques et dynamiques
  • Playbooks, modules, rôles, handlers
  • Variables, Facts, templates Jinja2
  • Ansible Vault pour les secrets
  • Déploiements sur AWS et DigitalOcean
Kubernetes (Orchestration)
  • Architecture : control plane, nodes, etcd, kubelet
  • Objets : Pods, Deployments, Services, ReplicaSets
  • ConfigMaps, Secrets, Volumes persistants
  • Networking : Ingress, NetworkPolicies
  • Autoscaling (HPA) et sondes de santé
  • Déploiement sur GKE (GCP) et AKS (Azure)
📚 Formations Dyma recommandées (dans cet ordre)
Formation AWS — EC2, S3, IAM, Lambda, VPC, RDS, CloudFront, projets réalistes dyma.fr/formations/aws ↗
Formation Terraform & OpenTofu — IaC HCL, AWS, multi-env, CI/CD, Checkov, certification Associate dyma.fr/formations/terraform-opentofu ↗
Formation Ansible — Playbooks, rôles, Jinja2, Vault, AWS, DigitalOcean dyma.fr/formations/ansible ↗
Formation Kubernetes — Cluster, Pods, Services, Ingress, autoscaling, GKE, AKS dyma.fr/formations/kubernetes ↗
AWS Terraform OpenTofu Ansible Kubernetes kubectl Minikube Helm GKE / AKS HCL Vault Checkov
🏁 Jalon — Passer à la Phase 6 quand vous pouvez :
  • Déployer une infrastructure complète sur AWS via Terraform avec pipeline CI/CD
  • Configurer automatiquement des serveurs avec des playbooks Ansible idempotents
  • Déployer une application multi-conteneurs sur un cluster Kubernetes avec autoscaling
  • Gérer les secrets en production (Vault ou AWS Secrets Manager)
  • Provisionner un cluster Kubernetes managé (GKE ou AKS) depuis du code Terraform
PHASE
06

Monitoring, Sécurité & Spécialisation

⏱ 4 à 6 semaines Expert
Monitoring & Observabilité
  • Prometheus : collecte de métriques, alertes
  • Grafana : dashboards et visualisation
  • ELK Stack ou Loki pour la centralisation des logs
  • Tracing distribué (OpenTelemetry)
  • SLO, SLI, SLA — culture SRE
Sécurité DevSecOps
  • Scan de vulnérabilités dans les pipelines CI/CD
  • Gestion des secrets (Vault, AWS Secrets Manager)
  • Durcissement des images Docker (rootless, non-root)
  • Network policies Kubernetes
  • RBAC et IAM avancé
Cloud avancé (optionnel)
  • Formation Azure sur Dyma pour le multi-cloud
  • Service mesh (Istio, Linkerd)
  • ArgoCD pour le GitOps
  • Helm charts pour le packaging Kubernetes
Projet de synthèse
  • Infrastructure complète sur AWS via Terraform
  • Cluster Kubernetes déployé en IaC
  • Pipeline CI/CD end-to-end (GitHub Actions)
  • Monitoring Prometheus + Grafana
  • Tout versionné sur GitHub, tout documenté

Cybersécurité — Vulnérabilités, durcissement systèmes, DevSecOps dyma.fr/formations/devops-clouds ↗
Prometheus Grafana ELK / Loki ArgoCD Helm Istio Azure Trivy OWASP
🏁 Jalon final — Profil DevOps Junior/Confirmé :
  • Vous avez un projet GitHub public avec infrastructure complète en IaC
  • Vous pouvez décrire et démontrer un pipeline CI/CD end-to-end en entretien
  • Vous avez des dashboards Grafana opérationnels sur votre cluster Kubernetes
  • Vous êtes capable de diagnostiquer une panne en production via les logs et métriques
  • Vous maîtrisez au moins un cloud provider (AWS recommandé) et deux outils IaC
